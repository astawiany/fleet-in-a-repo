# Security of the published artifacts

`release.yml` publishes two artifacts to the GitHub Container Registry when a `chart-vX.Y.Z` tag is
pushed. This page says what they are, how to verify them before use, how a release is cut, and what
the process does not guarantee.

Status: the release workflow is statically tested and its build, scan, push and chart steps were
rehearsed locally against a throwaway registry, but it has not yet run on GitHub. Nothing has been
published so far.

## What is published

| Artifact | Reference | Contents |
|---|---|---|
| App image | `ghcr.io/astawiany/fleet-demo:<version>` | linux/amd64; distroless `static-debian12:nonroot` base (pinned by digest) plus one static Go binary `/demo`; OCI labels `source`, `revision`, `version`, `licenses=MIT`, `title` |
| Image attestations | attached to the image index | SPDX SBOM and SLSA provenance (`mode=max`) generated by BuildKit |
| Helm chart | `oci://ghcr.io/astawiany/charts/demo`, version `<version>` | `values.yaml` pins the image by digest: `image.digest` = the image signed in the same release |
| Signatures | stored next to each artifact in the registry | keyless cosign (Sigstore) signatures of the image digest and the chart digest, logged in the public Rekor transparency log |

The image index digest is what gets signed. The index lists the attestation manifests, so the
signature also covers the SBOM and provenance.

Before anything is pushed the image job fails on: a fixable HIGH or CRITICAL vulnerability in the
image, any secret in the image or the repository, a HIGH or CRITICAL misconfiguration in the chart or
the Dockerfile (Trivy), or a vulnerable Go function the code actually calls (govulncheck). After the
push it checks that the pushed image has the same config digest as the scanned one.

## Verify before use

Requirements: `cosign` 3.x (releases are signed with the cosign version pinned in `versions.env`),
`docker` with buildx, `helm` 3.8 or newer, `jq`, `yq`.

```sh
VERSION=0.1.0   # without the chart-v prefix
IDENTITY='^https://github\.com/astawiany/fleet-in-a-repo/\.github/workflows/release\.yml@refs/tags/chart-v[0-9]+\.[0-9]+\.[0-9]+$'
ISSUER=https://token.actions.githubusercontent.com
```

The identity matches only `release.yml` of this repository running for a `chart-vX.Y.Z` tag, for
example `https://github.com/astawiany/fleet-in-a-repo/.github/workflows/release.yml@refs/tags/chart-v0.1.0`.
A signature made by any other workflow, branch or repository does not match it. It is only as
strong as the tag ruleset (see the threat model).

For a known version, also check the exact identity of that tag, so a signature from another
release tag cannot stand in for it:

```sh
cosign verify "ghcr.io/astawiany/fleet-demo@$DIGEST" \
  --certificate-identity "https://github.com/astawiany/fleet-in-a-repo/.github/workflows/release.yml@refs/tags/chart-v$VERSION" \
  --certificate-oidc-issuer "$ISSUER"
```

Image: resolve the tag to a digest once, verify that digest, then use only the digest.

```sh
DIGEST="$(docker buildx imagetools inspect "ghcr.io/astawiany/fleet-demo:$VERSION" --format '{{json .Manifest}}' | jq -r .digest)"
cosign verify "ghcr.io/astawiany/fleet-demo@$DIGEST" \
  --certificate-identity-regexp "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER"
```

Chart: pull it, verify the digest `helm pull` printed, then install the verified local file.

```sh
CHART_DIGEST="$(helm pull oci://ghcr.io/astawiany/charts/demo --version "$VERSION" 2>&1 | sed -n 's/^Digest: //p')"
cosign verify "ghcr.io/astawiany/charts/demo@$CHART_DIGEST" \
  --certificate-identity-regexp "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER"
tar -xzOf "demo-$VERSION.tgz" demo/values.yaml | yq '.image'   # digest must equal $DIGEST
helm install demo "./demo-$VERSION.tgz"
```

The chart renders `ghcr.io/astawiany/fleet-demo@<digest>`, so `image.tag` is ignored while
`image.digest` is set. To run another image, set `image.digest=""` and `image.tag` explicitly.

SBOM and provenance (both are part of the signed index):

```sh
docker buildx imagetools inspect "ghcr.io/astawiany/fleet-demo@$DIGEST" --format '{{json .SBOM}}' | jq '.SPDX.packages[].name'
docker buildx imagetools inspect "ghcr.io/astawiany/fleet-demo@$DIGEST" --format '{{json .Provenance}}' | jq '.SLSA'
```

The provenance names the source repository, the commit (`vcs.revision`), the build arguments and
the base image digests.

## Threat model

1. The identity matches any `.github/workflows/release.yml` running for a `chart-vX.Y.Z` tag, with
   whatever content that file has at the tagged commit: it names the file and the tag, not the code.
2. So the control is who can create `chart-v*` tags. `scripts/protect-branch.sh` creates the ruleset
   `release-tags` by default: only repository admins can create, move or delete them. The signing
   guarantee holds only while that ruleset is active; without it any writer can push a branch with
   a modified `release.yml` (no `verify`, no Environment), tag it and get a matching signature.
3. The `verify` job (tag format, commit on `main`, version not yet published) and the `release`
   Environment are procedural gates: they bind only the `release.yml` that calls them.
4. `main` changes only through reviewed pull requests (branch protection, CODEOWNERS), so the
   reviewed `release.yml` keeps those gates for tags an admin cuts from `main`.
5. A tag pusher who is also the only `release` reviewer can approve their own release. With more
   than one reviewer, enable "Prevent self-review" (`prevent_self_review`) on the Environment.
6. Not blocked: a writer can push a workflow on another branch that uses `GITHUB_TOKEN` with
   `packages: write` and overwrites a tag on GHCR. Such an image has no matching signature.
7. Tags on GHCR are mutable: always resolve a tag once, verify the digest, and deploy by digest.
8. A compromised base image, Go module or tool upstream is limited by digest and checksum pins and
   by the scans, not excluded.
9. `GITHUB_TOKEN` is the only credential; there are no long-lived registry or signing keys to leak.
10. Signing identities and digests are public in Rekor; nothing secret is signed.

## Release procedure

0. Once per repository: apply branch protection, the Environments and the tag ruleset:
   `scripts/protect-branch.sh --repo astawiany/fleet-in-a-repo --reviewers <login>` (preview with
   `--dry-run`; see [.github/README.md](../.github/README.md)).
1. Merge the change to `main` and bump the version: `apps/demo/chart/Chart.yaml` is informative,
   the tag decides the published version.
2. Create the tag from `main` (only admins can, through the ruleset):
   `git tag chart-v0.1.0 origin/main && git push origin chart-v0.1.0`.
3. `release.yml` runs `verify` (tag format, commit on `main`, version not yet in the registry).
4. Approve the `release` Environment for the `image` job, then again for the `chart` job (each job
   in an Environment asks for its own approval). Check the job summaries: they list both digests.
5. Verify both artifacts with the commands above.
6. First release only: make the packages public (next section).

A version is never overwritten: to fix a release, push a new tag with a higher version.

## GHCR packages

- The first push creates each package as private, owned by the account `astawiany`. The image's
  `org.opencontainers.image.source` label links `fleet-demo` to this repository.
- To publish, after verifying: GitHub > your profile > Packages > `fleet-demo` > Package settings >
  Danger Zone > Change visibility > Public (`https://github.com/users/astawiany/packages/container/fleet-demo/settings`).
  Do the same for `charts/demo` (`https://github.com/users/astawiany/packages/container/charts%2Fdemo/settings`).
  Making a package public cannot be undone for that package.
- Check visibility (needs a token with `read:packages`):
  `gh api users/astawiany/packages/container/fleet-demo --jq .visibility` and
  `gh api users/astawiany/packages/container/charts%2Fdemo --jq .visibility`.
- The chart package carries no source label: link it to the repository in its Package settings if
  you want it listed on the repository page.

## Not covered

- No reproducible-build proof: nobody rebuilds the image independently and compares digests,
  although the build is deterministic for a given commit (fixed timestamps, no VCS stamping).
- No SLSA level is claimed. The provenance attestation is produced by BuildKit inside the same job
  that builds the image; it is not generated by an isolated, non-forgeable builder.
- The scans are a point-in-time gate on the day of the release. Vulnerabilities published later are
  not reported for released versions; rescan by digest (`trivy image ghcr.io/astawiany/fleet-demo@<digest>`).
- Only linux/amd64 is built.
- The SBOM and provenance are not signed separately; they are covered by the signature of the
  image index that lists them.
